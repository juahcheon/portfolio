# 사람인 취업 지원 — 후임에게 넘기는 작업 기준

우리가 맡은 일은 지원자의 경험을 확인하고, 그 경험이 필요한 회사에 맞게 설명하고, 실제로 무엇이 제출됐는지 확인하는 데까지다. 글을 잘 쓰는 것과 지원을 끝내는 것은 다른 단계다. 아래 기준으로 둘 다 마무리한다.

## 먼저 오늘의 범위를 구분한다

| 요청 | 할 일 | 읽을 문서 |
|---|---|---|
| “오늘도 5곳 지원해” | 공고 선별 → 회사별 자기소개서 → 순차 지원 → 제출본 검증 → 기존 HTML 갱신 | [공고·글쓰기](references/screening-and-writing.md), [사람인 실행](references/saramin-execution.md), [기록·인계](references/records-and-portability.md) |
| “포트폴리오와 이력서 내용을 고쳐” | 경험 근거 조사 → 포트폴리오 검토본 → 사용자 최종 확인 → 기존 디자인의 PDF → 사람인 내용·첨부 교체 | [경험·문서](references/evidence-and-documents.md) |
| “회사 정보·지원 내용을 정리해” | 실제 제출본과 공고를 바탕으로 기존 HTML 누적 갱신 | [기록·인계](references/records-and-portability.md) |
| “공고 URL만 줘 / 지원 준비만 해” | 요청한 결과까지만 진행 | [공고·글쓰기](references/screening-and-writing.md) |

스킬을 읽었다는 사실은 지원·전송 승인이 아니다. 현재 대화에서 사용자가 요청하거나 승인한 범위를 따른다. 이미 승인한 회사·내용을 같은 조건으로 제출할 때 승인을 반복해서 묻지 않는다. 사용자가 URL만 원했다면 지원하지 않는다.

## 새 환경에서 시작하는 법

1. 작업 저장소의 `AGENTS.md`와 관련 하위 지침, 최신 사용자 메시지를 읽는다. 현재 날짜·시간대를 확인한다.
2. 현재 폴더와 연결된 프로젝트에서 포트폴리오 원본, PDF 생성 소스·최종 PDF, 경험 정리, 기존 지원 기록·HTML을 찾는다. 문서에 적힌 경로가 낡았다면 실제 소비 코드까지 확인한다. 특정 드라이브·사용자 폴더·파일명·브라우저 탭 ID를 가정하지 않는다.
3. 사용자가 지정한 브라우저·탭과 계정을 현재 도구로 확인한다. `@Chrome`이 있으면 Chrome부터 찾는다. 연결 상태를 보기도 전에 URL을 못 본다며 사용자에게 다시 찾으라고 하지 않는다.
4. 기존 지원 내역과 오늘의 요청을 대조한다. 기록이 이 컴퓨터에 없다는 이유로 지원 이력이 없다고 판단하지 않는다. 사람인·외부 채용사이트의 실제 내역을 확인한다.
5. 이미 확인된 선호·경력·승인은 이어받는다. 확인할 수 없는 필수 정보만 묻고, 답변 없이 가능한 조사·초안 작업은 계속한다. 개인 설정이 필요하면 [설정 예시](assets/private-profile.example.json)를 비공개 작업 폴더에 복사한다.

## 이 작업에서 합의한 기본값

다음은 이 저장소 소유자와 정한 기본값이다. 최신 요청이 우선하며, 다른 지원자에게 재사용할 때는 그 사람의 조건으로 바꾼다.

| 항목 | 기본값 |
|---|---|
| 일일 목표 | “오늘도”라는 연속 요청은 새로 지원하는 5곳. 명시된 수가 있으면 그 수 |
| 마감 | **마감 임박 순**. 이미 마감된 공고 제외, 정확한 일시와 조기 마감 여부 확인 |
| 직무 | 프론트엔드 우선. 기본 소개는 프론트엔드 강점을 가진 **웹 개발자** |
| 경력 조건 | 신입·경력 무관·최소 경력 2년까지 검토. 실제 근무기간을 늘려 쓰지 않음 |
| 회사·지역 | 어느 정도 규모가 있는 회사 선호. 마포·홍대·김포·마곡·마곡나루·발산·강남 우선, 그 외도 조건이 좋으면 검토 |
| 출퇴근 | 약 1시간을 선호하되 출발지는 현재 정보로 확인. 과거 거주지를 현재 주소로 사용하지 않음 |
| 일일 지원 수정 범위 | 사람인 **자기소개서 중심**. 기존 PDF·포트폴리오·학력·경력은 별도 요청 없이 매번 수정하지 않음 |
| 글의 소재 | 최근 실무·인턴 경험 우선. 공고에 더 맞으면 이전 직장·프로젝트 경험도 사용 |
| 문단 | 사람인 입력 원고는 **줄바꿈 한 번(`\n`)**. 탭 문자, 빈 문단, 두 번 이상의 줄바꿈을 넣지 않음 |

희망연봉·입사 가능일·주소·재직 여부는 시점과 지원 건에 따라 달라진다. 이 스킬에 과거 값을 박아 넣지 말고 최신 확인값과 확인일을 사용한다. 병역·장애·보훈 등도 다른 사람이나 성별만 보고 추정하지 않는다.

## 절대 놓치지 않을 작업 기준

- **경험을 만들지 않는다.** 실제 코드·변경 이력·사용자 설명에 근거하고 본인과 동료의 기여를 구분한다. 회사에 맞추는 것은 소재와 설명의 순서다.
- **공고 전체를 읽는다.** 회사소개, 이미지 본문, 첨부, 지원 페이지까지 확인한다. 필수 서류·자기소개서 파일·지정 양식을 뒤늦게 발견하지 않도록 한다.
- **사용자의 의견이 필요한 질문은 하나씩 한다.** 동기·생각·없는 경력 사실을 지어내지 않는다. 일반적인 문장 다듬기나 이미 승인된 제출을 다시 허락받지는 않는다.
- **PDF 디자인은 보존한다.** 내용 수정 요청으로 레이아웃·폰트·색·이미지를 갈아엎지 않는다. AI Switch도 다른 프로젝트처럼 공개 가능한 실제 작업 화면을 유지한다.
- **한 회사씩 끝낸다.** A사 글 저장 → 새 지원 화면에서 A사 확인 → 제출 → 실제 제출본 대조를 마친 뒤 B사 글로 바꾼다.
- **제출 오류와 미제출은 다르다.** 버튼 후 시간 초과가 나면 지원 내역부터 확인한다. 결과를 모르는 상태에서 재제출하지 않는다.
- **완료는 증거로 판단한다.** 저장 버튼 클릭·초안 작성·지원창 열기는 지원 완료가 아니다. 미확인 상태를 성공으로 집계하지 않는다.
- **HTML은 누적 기록이다.** 기존 회사·제출 원고·PDF 버전·메모·체크 상태를 보존하며 추가한다. 면접 준비용 초안을 실제 제출 글처럼 기록하지 않는다.

## 실행과 마무리

선별 근거와 회사별 원고를 검토 가능한 형태로 먼저 만든다. 실제로 새 승인이 필요한 경우에만 회사·전달 정보·첨부·예외 조건을 한 번에 제시하고 마지막 제출 직전에 묻는다. 현재 브라우저 도구의 승인·인증 규칙은 별도로 지킨다.

형식 및 제출 원고 대조에는 [검사 스크립트](scripts/check_application_records.py)를 사용할 수 있다. Python 3 표준 라이브러리만 사용하며, 파일 검사만 한다. 브라우저를 조작하거나 지원 상태를 바꾸지 않는다.

```text
python <스킬폴더>/scripts/check_application_records.py <회사별원고.json>
python <스킬폴더>/scripts/check_application_records.py <회사별원고.json> --submitted <실제제출본.json>
```

사용 가능한 실행 파일이 `python3` 또는 `py`라면 그 이름을 사용한다. 레코드 형식과 검증 한계는 [기록·인계](references/records-and-portability.md)를 읽는다. 이 스크립트의 통과는 경력 사실이나 웹사이트 제출 성공을 증명하지 않는다.

마지막에는 **실제 완료한 회사와 수, 남은 예외, 갱신한 HTML 경로**를 간단히 알린다. 작업 중단 시에는 마지막으로 검증한 회사와 다음 단계, 사람인에 현재 저장된 자기소개서의 대상을 남긴다.

## 다른 컴퓨터에서 사용하기

이 폴더 전체를 보존한다. `SKILL.md`만 복사하면 상세 절차와 검사기가 빠진다.

- **이 저장소에서:** 이 스킬이 포함된 브랜치를 내려받고 저장소를 Codex에서 연다. `.agents/skills/saramin-job-application`은 저장소 스킬 위치다.
- **다른 저장소에서도:** 폴더 전체를 사용자 홈의 `.agents/skills/saramin-job-application`에 복사하거나, `$skill-installer`에게 이 저장소의 해당 경로·브랜치를 지정해 설치를 요청한다. 같은 이름을 여러 경로에 중복 설치하지 않는다.
- **호출:** `$saramin-job-application 오늘도 5곳 지원해줘. 기존 지원 내역부터 확인해.` 인식되지 않으면 새 세션을 열거나 Codex를 재시작한다.
- **다른 에이전트:** 그 제품의 스킬 설치 위치에 폴더 전체를 두고 `SKILL.md`를 읽도록 한다. 브라우저 제어·로그인·파일 접근 능력은 해당 환경에 있어야 한다.

로컬 스킬 경로와 인식 방식은 [OpenAI 공식 문서](https://learn.chatgpt.com/docs/build-skills)에 따른다(2026-10-01 확인). 실제 이력서·지원 내역·로그인은 스킬에 포함되지 않는다. 다른 컴퓨터에서는 본인의 비공개 자료를 옮기거나 접근 권한을 연결해 이어간다. 연결이 없으면 조사·초안까지 진행하고 필요한 연결만 안내한다.
