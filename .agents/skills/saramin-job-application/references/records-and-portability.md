# 지원 기록과 다른 컴퓨터로의 인계

## 공유하는 절차와 개인 자료를 분리한다

스킬에는 판단 기준·순서·빈 설정 예시·검사기만 둔다. 실제 연락처, 정확한 주소, 증명사진, 희망연봉, 지원서, 접수 번호, 인증값, 비공개 회사 자료와 PDF가 내장된 HTML은 함께 커밋하지 않는다. 이미 공개된 포트폴리오도 채용용 비공개 자료 전체를 공개하는 동의로 해석하지 않는다.

개인 자료는 사용자가 지정한 비공개 폴더 또는 저장소의 Git 제외 폴더에 둔다. 이 저장소의 새 작업 자료는 `.job-search/`를 사용할 수 있다. 기존 `output/`에 기록이 있으면 그대로 찾아 읽되 그 폴더 전체를 stage하지 않는다. 파일명에 `private`가 있어도 Git 제외가 자동 적용되는 것은 아니다. `git check-ignore`와 실제 stage 목록을 확인한다.

[private-profile.example.json](../assets/private-profile.example.json)은 `.job-search/profile.json` 등에 **복사한 뒤** 채운다. 공유 예시 원본에 개인정보를 넣지 않는다. 예시의 `null`은 “없음”이 아니라 “아직 확인 안 됨”이다. 경로는 개인 설정 파일 기준의 상대 경로로 해석하고, 다른 컴퓨터에서는 존재 여부를 다시 확인한다.

이전 지원 내역이 없으면 현재 사이트의 지원 기록과 사용자 자료로 복원한다. 외부 사이트 지원은 사람인 목록만으로 빠짐없이 알 수 없으므로 이전 기록도 확인한다. 누락 범위를 남기고, “지원한 곳 없음”으로 초기화하지 않는다.

## 기록할 단위

회사명만 키로 쓰면 같은 회사의 다른 직무가 덮어써진다. 기록 `id`는 지속되는 고유 값으로 정하고 플랫폼·공고 ID·직무·접수 ID를 함께 보관한다.

| 분류 | 기록할 내용 |
|---|---|
| 공고 | 회사·직무·URL·공고 ID·확인일·마감 일시·근무지·고용 형태·필수/우대 조건 |
| 회사 | 사업·제품·규모와 기준일·출처, 지원자와 맞는 점, 아직 확인할 점 |
| 원고 | 회사별 자기소개서의 항목 제목·본문, 근거 사례, 검토/저장 버전 |
| 첨부 | PDF 파일명·버전·가능하면 해시, 실제 제출한 포트폴리오 URL 목록 |
| 진행 | 준비/보류/승인됨/제출 결과 미확인/접수 확인/제출본 검증 완료/제외, 그 이유 |
| 제출 | 사이트에서 읽은 접수 시각·번호·제출본 URL·실제 원고·검증 결과 |
| 면접 준비 | 지원동기 요약, 예상 질문, 경험 복습, 회사에 물을 질문 |

“완료 버튼을 누름”과 “접수 확인”을 나눠 기록한다. 수정 중인 원고로 과거 제출 원고를 덮어쓰지 않는다. 승인 범위는 비공개 진행 기록에 남기며 예전의 승인을 새로운 회사에 확대하지 않는다.

## 검사 스크립트 입력

UTF-8 JSON 배열을 받는다. 기존 일일 지원 JSON과 맞추기 위해 아래 필드 이름을 사용한다. 상세 회사 정보 등 추가 필드는 보존해도 된다.

```json
[
  {
    "id": "example-company-frontend-01",
    "company": "예시 회사",
    "role": "프론트엔드 개발자",
    "platform": "saramin",
    "recIdx": "example-posting",
    "status": "검토 중",
    "introductions": [
      {
        "title": "문제 해결 경험",
        "text": "실제 확인한 경험을 작성한다.\n다음 문단은 줄바꿈 한 번으로 구분한다."
      }
    ]
  }
]
```

위 회사와 공고 ID는 사용 예시다. 실제 지원이나 제출 증거로 쓰지 않는다. 회사별 문항 수는 달라도 되며 일반적으로 기존 4항목을 유지한다.

검사기는 빈 항목·중복 식별자·빈 문단·탭·중복 제목 등을 검사한다. `verified: true`인 기록은 실제 확인한 `submittedAt`, `applicationId`, `submittedResumeUrl` 또는 `receiptEvidence`가 필요하다. `receiptEvidence`는 확인한 접수 화면/파일의 위치나 설명을 담는다. 스크립트는 해당 사이트나 파일을 열어 접수 성공을 검증하지 않는다.

`--submitted` 파일도 같은 배열 형식으로 만든다. **그 안의 문장은 사이트에서 읽은 제출본에서 가져온다.** 같은 `id`로 대응하고 회사·직무·공고·플랫폼, 전체 자기소개서의 순서·제목·본문을 비교한다. 기대 파일에 접수 ID나 `attachments`가 있다면 제출본에도 동일한 값을 기록해야 한다. 기대 파일의 일부 회사만 대조하려면 그 회사들을 담은 별도 입력 파일을 만들고, 원본 누적 파일을 잘라 덮어쓰지 않는다.

정규화는 CRLF/CR → LF와 NBSP → 일반 공백만 한다. 그 밖의 띄어쓰기·문단·순서 차이는 숨기지 않는다. `--submitted` 없이 실행한 결과는 형식 검사일 뿐이며, `--submitted`도 입력 파일끼리의 대조다. 인간적인 문체·허위 경험·공고 적합성은 직접 읽어서 판단해야 한다.

```text
python <스킬폴더>/scripts/check_application_records.py .job-search/drafts.json
python <스킬폴더>/scripts/check_application_records.py .job-search/drafts.json --submitted .job-search/submitted.json
```

오류는 레코드 번호·필드만 출력하고 원고나 개인정보 전체를 로그에 찍지 않는다. 종료 코드 0은 통과, 1은 검수 오류, 2는 입력 파일·형식 오류다. 원본 파일은 수정하지 않는다.

## HTML 지원 노트 갱신

사용자가 “어제 그 HTML”이라고 하면 기존 파일과 생성 소스를 찾아 수정한다. 새 날짜 파일만 만들어 과거 기록을 놓치지 않는다. 기존 디자인과 메모·체크박스용 `id`·저장 키를 보존한다.

회사마다 다음을 읽기 쉽게 보여 준다.

1. 회사·사업·채용 직무·규모·근무지·고용 조건·마감·공고 링크와 정보 기준일.
2. 실제 지원일·지원 구분·첨부·회사별 **실제 제출 자기소개서**와 확인 상태.
3. 지원 이유 요약, 면접 예상 질문, 복습할 경험, 회사에 확인할 사항.

기존에 카드·탭·검색·체크리스트가 있으면 그대로 유지한다. 새로운 기록이 전혀 없을 때만 단순한 HTML 파일로 시작한다. 서버·새 패키지·DB가 필요하지 않다. 텍스트는 HTML 이스케이프하고 링크는 의도한 주소인지 확인한다.

검수할 때는 기존 회사 수·원고 수가 줄지 않았는지, 새 회사 중복이 없는지, 전체·일자별 완료 수가 실제 기록과 맞는지 확인한다. 사람인에서 시작해 외부 사이트에서 접수한 한 건을 두 번 세지 않는다. 실제 제출 글과 면접용 새 초안을 명확히 구분한다.

PDF를 HTML에 내장한 기존 방식이라면 과거 지원에 쓴 버전까지 보존한다. 큰 base64와 개인 자료가 포함될 수 있으므로 공개 저장소나 공개 호스팅에 자동 배포하지 않는다. 사용자가 승인한 로컬 미리보기 도구로 열어 한글·탭·링크·레이아웃을 확인한다.

## 다른 컴퓨터 또는 후임에게 넘길 최소 상태

```text
기준일과 시간대 / 현재 요청 / 이미 승인된 범위
포트폴리오·PDF 원본·최종본 경로와 버전
경험 근거 파일과 마지막 확인 범위
기존 지원 목록 및 복원되지 않은 범위
오늘 후보별 상태와 마지막 확인 증거
사람인에 현재 저장된 회사별 원고 대상
대기 중인 질문·로그인·필수 서류 / 다음에 할 한 단계
```

로그인 쿠키·인증번호를 옮기는 인계 파일은 만들지 않는다. 문서와 상태를 사용자 허가 범위에서 옮기고 새 브라우저에서 로그인한다. 탭 번호는 새로 찾는다.

## 스킬을 고칠 때의 확인 사례

| 시험 상황 | 올바른 판단 |
|---|---|
| 새 컴퓨터, 로컬 이력 없음, 사용자는 “계속” | 기존 사이트·자료로 이력 확인. 무조건 처음 5곳부터 지원하지 않기 |
| 최소 경력 2년 공고, 실제 경력은 짧음 | 지원 가능성 검토하되 날짜·기간 유지 |
| A사 승인 후 B사 글이 현재 저장됨 | A사 글을 저장·재확인하고 A사 지원창을 새로 열기 |
| 최종 제출 클릭 뒤 시간 초과 | 접수 내역부터 확인, 중복 클릭 금지 |
| 필수 경력증명서가 없고 사용자가 교체 지시 | 해당 공고 제외·새 후보 탐색, 증명서 창작 금지 |
| 문단 사이 공백만 있는 줄 또는 NBSP 줄 | 형식 오류로 잡고 한 번 줄바꿈으로 수정 |
| 아직 병합 안 된 작업을 배포 성과로 소개 | 실제 단계로 표현을 낮추거나 다른 확인된 사례 선택 |
| 같은 5곳에 대한 승인 유지, 조건 변경 없음 | 재승인 질문 없이 승인 범위 안에서 진행 |
| 일일 지원 요청 | 자기소개서 중심 수정, PDF를 회사마다 재생성하지 않기 |

스킬·검사기를 시험한다고 실제 지원을 보내지 않는다. 형식과 비교는 비공개 임시 폴더의 합성 데이터로 검사하고, 실제 제출 확인은 승인된 지원 작업에서만 수행한다.
