AI Switch

개요기업과 기관을 위한 생성형 AI 플랫폼
개발 방식AI 코딩 도구를 활용한 바이브 코딩. 요구사항과 수정 범위를 정의하고, 제안 코드 검토와 수정, 동작 검증을 직접 담당했습니다.
사용 기술React, Vite, TypeScript
관련 링크ax.aiswitch.co.kr
작업 영역주요 기여
UI/UX디자인 토큰과 CSS 변수를 정리하고 이미지 및 비디오 스튜디오, 공공자료의 출처와 추천 질문을 채팅으로 연결하는 UX를 개선했습니다.
인증 / 계정소셜 로그인과 계정 연결을 구현했습니다. 개인 Google 로그인과 조직 SSO를 분리하고 공통 로그아웃 흐름으로 콜백 오류와 인증 쿠키 잔존 문제를 해결했습니다.
관리자 / API관리자 및 조직 콘솔의 반응형 UI, 목록 API의 검색, 정렬, 페이지네이션과 다국어 오류 안내를 정비했습니다.

트러블슈팅

이미지 생성 중 연결 끊김, 서버 상태를 다시 확인해 결과 표시

문제 상황

이미지 생성 중 SSE 연결이 끊기면 서버 작업이 진행 중이어도 화면에서 실패로 보일 수 있었습니다. 연결 상태와 실제 작업 상태를 분리해, 같은 작업의 결과를 이어 받아야 했습니다.

해결 및 결과

작업 ID를 보존하고 서버 상태 API를 폴링해 완료, 실패를 복구했습니다. 사용자 취소 시 조회를 중단하고, 단절 후 복구와 잘못된 ID 차단을 포함한 서비스 및 화면 테스트 17개를 통과했습니다.

로그인 이동 오류와 자동 재로그인, 로그인 설정과 로그아웃 수정

문제 상황

개인 Google 로그인과 조직 SSO의 콜백 설정이 섞여 다른 도메인으로 복귀했습니다. 프로필 로그아웃도 서버의 HttpOnly 쿠키를 정리하지 못해 즉시 재로그인됐습니다.

해결 및 결과

소셜 로그인 전용 콜백 설정을 분리하고, 프로필 로그아웃을 공통 인증 처리에 연결했습니다. 콜백 관련 테스트 14개, 로그아웃 관련 테스트 8개와 타입 검사를 통과해 기존 오류의 재발을 점검했습니다.

AI Switch Docs

개요사용자와 관리자를 위한 공식 문서 사이트
개발 방식Codex, Claude Code를 활용한 바이브 코딩. 문서 구조와 자동화 규칙을 설계하고, 제안 코드를 검토하며 경로와 콘텐츠 검증을 담당했습니다.
사용 기술Astro, Starlight, React, TypeScript
관련 링크공식 문서 | 튜토리얼 | 업데이트 소식
작업 영역주요 기여
문서 / 검색기존 가이드를 Astro, Starlight로 이관해 5개 언어 문서와 검색을 구축하고, 역할별 메뉴, 사이드바, FAQ, 목차를 개선했습니다.
튜토리얼관리자 설정 튜토리얼과 다국어 PDF, 스크린샷 확대 기능을 구현하고, AI 모델 탐색 및 비교 화면을 문서 앱에 통합했습니다.
검수 / 자동화언어별 콘텐츠와 스크린샷 검수를 자동화했습니다. 월별 업데이트 소식 작성 스킬과 팀용 사용 가이드를 만들어 같은 조사, 작성, 검수 절차를 재사용하도록 구성했습니다.

트러블슈팅

선택한 언어가 바뀌는 문제, 접속 경로별 언어 설정 분리

문제 상황

외부 링크 진입에는 브라우저 언어를, 내부 탐색에는 사용자가 고른 언어를 적용해야 했습니다. 동일한 규칙과 캐시를 쓰면 언어 선택이 뒤집히거나 다른 언어의 이동 응답이 재사용될 수 있었습니다.

해결 및 결과

외부 진입과 내부 탐색의 규칙을 분리하고, 언어 이동 응답에 no-store를 적용했습니다. 5개 언어 문서 285개의 경로와 메타데이터를 검증하고 관련 회귀 테스트를 통과해 이동 규칙을 확인했습니다.

매달 반복하던 소식 작성, AI로 자료 수집부터 검수까지 자동화

문제 상황

월별 업데이트마다 커밋과 PR을 조사하고 원고, 이미지를 검수하는 작업이 반복됐습니다. 새 소식이 없는데도 원고나 수정일을 바꾸거나, 이전 링크와 출처를 잃지 않는 기준이 필요했습니다.

해결 및 결과

대상 월을 지정하면 이력 수집부터 작성, 검증까지 수행하는 스킬과 팀용 가이드를 만들었습니다. 링크와 출처 보존을 회귀 테스트로 검증했습니다. 기존 시스템의 구성과 표현 방식을 유지하며 필요한 소식만 선별하고, 사용자 이해를 돕는 이미지를 제작해 개발팀 전원의 만족을 얻었습니다.

트러블슈팅

느린 사진과 반복되는 목록 조회, 원본 사진과 저장된 목록 활용

문제 상황

지도 사진의 요청 경로를 추적해 Next.js /_next/image의 리사이징 처리로 로딩이 지연되는 것을 확인했습니다. 지도 재진입 때 발생하는 목록 API의 반복 요청은 이미지 처리와 별개로 줄여야 했습니다.

해결 및 결과

지도 사진과 확대 화면에만 unoptimized를 적용해 원본 URL을 직접 요청하고 리사이징 대기를 줄였습니다. 당시 Network 탭 관찰상 로딩 시간은 약 10초에서 2초 수준으로 감소했습니다. 목록 API에는 5분 staleTime을 적용해 재진입 시 유효한 캐시를 재사용했습니다.

테스트 화면의 잘못된 서버 연결, 접속 주소에 따라 서버 구분

문제 상황

테스트 도메인만 따로 분류하고 나머지를 운영으로 보내는 구조였습니다. 새 프리뷰 도메인이 추가되면 별도 등록 없이 운영 API를 사용해 운영 데이터에 영향을 줄 수 있었습니다.

해결 및 결과

API와 로그인 복귀 주소에 운영 도메인 허용 목록을 적용하고, 미등록 호스트는 테스트로 분류했습니다. 두 환경의 URL이 설정된 조건에서 운영, 테스트, 로컬, 미등록 도메인의 함수 입력과 URL 선택 결과를 검증했습니다.
