## 필요한 일을 찾아 제안하고 구현합니다

저는 맡은 일을 마친 뒤에도 팀에 필요한 일이 있는지 먼저 묻는 편입니다. 상상력집단에서 약 3개월간 인턴으로 근무하며, 백엔드·인프라 업무가 중심인 개발팀에서 제가 기여할 수 있는 화면 개선 과제를 찾았습니다. 작은 글자와 일관되지 않은 색상·간격, 한곳에 모인 전역 스타일을 보며 개선이 필요하다고 제안했고, 개발팀과 합의한 뒤 작업을 진행했습니다.

색상·간격·타이포그래피 등을 공통 토큰으로 정리하고 전역 CSS를 역할별로 나눴습니다. 이때 기존 화면의 값이 의도치 않게 바뀌지 않도록 변환과 검증도 보완했습니다. 주도성은 일을 많이 벌이는 것이 아니라, 필요한 문제를 찾아 팀과 우선순위를 맞추고 실제 변경으로 완성하는 태도라고 생각합니다.

## 사용자가 다음 행동을 이해할 수 있는 화면을 만듭니다

AI Switch 이미지 스튜디오는 화면이 여러 영역으로 나뉘어 요소가 많았고, 어떤 프롬프트로 어떤 이미지를 만들 수 있는지 보여 주는 예시가 부족했습니다. 저는 사용자가 이미지를 만드는 순서를 기준으로 프롬프트·모델·규격·참조 이미지·생성 버튼을 하나의 입력 영역으로 모으고, 용도별 예시를 선택해 바로 활용할 수 있도록 구성했습니다.

공공자료 페이지도 업무별 카드에서 자료를 고르고 공식 출처와 추천 질문을 확인한 뒤 대화로 이어지도록 개편했습니다. 화면 구성뿐 아니라 카테고리별 URL과 세션 복원, 뒤로가기까지 함께 정리했습니다. 두 화면은 회사에서도 좋은 평가를 받았습니다. 보기 좋은 화면을 만드는 감각을 사용자의 목적과 실제 동작에 연결하는 것이 제 강점입니다.

## 화면의 문제를 요청과 상태의 흐름까지 따라가 해결합니다

AI Switch Ops에서는 응답이 자동 갱신 주기보다 느릴 때 진행 중인 요청이 반복 취소돼 데이터가 나타나지 않을 수 있었습니다. 갱신 간격만 늘리는 대신 요청이 끝난 뒤 다음 갱신을 예약하도록 바꾸고, 화면에 필요한 조회만 실행하도록 범위를 나눴습니다. 느린 메트릭과 워크로드 조회를 분리하고, 갱신 실패 시 마지막 성공 데이터와 당시 시각을 보존하되 최신 정보로 오해하지 않도록 상태를 구분했습니다.

또한 경과 시간·로그 입력이 목록 전체를 다시 그리지 않도록 상태를 분리하고 보조 화면을 지연 로딩했습니다. 동일 환경에서 기준 커밋을 다시 빌드한 비교 기록상 초기 JavaScript는 454.84KB에서 345.34KB로 약 24% 줄었습니다. 느린 응답, 이전 화면의 늦은 응답, 실패 후 재시도를 회귀 테스트로 확인하며 화면과 API를 함께 살펴보는 문제 해결 경험을 쌓았습니다.

## 반복 작업은 기준을 정리해 다시 사용할 수 있게 만듭니다

AI Switch Docs를 Astro·Starlight 기반의 5개 언어 공식 문서로 정리하며, 사용자가 필요한 안내를 같은 구조에서 찾을 수 있도록 가이드와 튜토리얼을 구성했습니다. 이후 요청받은 업데이트 소식 제작 업무에서는 매번 변경 내용을 전달받는 대신 GitHub 커밋·PR·diff에서 근거를 수집하는 AI 스킬을 만들고 팀 사용 가이드와 함께 공유했습니다.

월을 지정하면 새 소식을 선별하고 원고를 작성하도록 하되, 핵심 기능어가 드러나는 제목과 짧고 쉬운 문장, 실제 기능을 설명하는 이미지의 기준을 정했습니다. 기존 글의 날짜·링크를 보존하고 검증하는 절차도 포함했습니다. 입사 후에도 제품과 팀의 작업 방식을 먼저 이해하고, 사용자에게는 명확한 화면을, 동료에게는 다시 사용할 수 있는 코드와 작업 기준을 남기겠습니다.
